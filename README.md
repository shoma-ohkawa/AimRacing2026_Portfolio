# AimRacing2026 Portfolio

展示用に制作した、G923 ハンドルコントローラーと WIZMO モーションチェアで遊ぶ、3 画面出力のレーシングゲームです。

ポートフォリオ用に、自分が書いたソースと実行データを公開するリポジトリです。ソースは `Source/`、実行データは [Releases](https://github.com/shoma-ohkawa/AimRacing2026_Portfolio/releases) の zip です。

## 制作情報

| 項目 | 内容 |
|---|---|
| 制作 | 8 名(プログラマー 6 名、デザイナー 2 名) |
| 担当 | プログラマー(描画、パフォーマンス最適化、プロジェクト最適化) |
| 期間 | 2026 年 7 月〜(現在も継続中) |
| ジャンル | レーシング(展示用) |
| 開発環境 | Unity 6000.6.5f1 / C# / Visual Studio 2026 |
| 作成者 | 日本電子専門学校 ゲーム制作研究科 大川翔生 |

## 担当内容

プログラマーとして、描画、パフォーマンス最適化、プロジェクト最適化を担当しました。あわせて、ゲーム全体の進行の仕組みも書いています。

**描画**
- 3 画面出力: 1 台のカメラの映像を、接続されているモニターの数に合わせて分割表示
- レースに入るときのポストプロセス演出(ガウスぼかしの Custom Pass)
- 遷移のあいだ画面を覆う層(フェード、Loading 画面、タイトルロゴ)

**パフォーマンス最適化**
- 計測: FPS・CPU・GPU・メモリ・GC と、遷移・ロード時間の記録、自動周回、放置監視、集計とグラフ
- 周回でメモリと VRAM が増える原因の切り分け(主因は DLSS)
- リリースビルドの無駄なログ出力の削減(`AppLog`)と、前のプレイの状態のリセット・GC・アセットの回収

**プロジェクト最適化**
- C# の警告の整理、古い形式でシリアライズされたアセットの再保存による警告の解消
- Git / Git LFS の運用の準備
- プロジェクトを zip にまとめるエディタ拡張(ホワイトリスト方式)

**ゲーム進行**
- State 遷移エンジンと、各 State(Load / Splash / Opening / Menu / Intro / Racing / Result)の実装
- 共通基盤(シングルトン)と、カーブ標識を調整するエディタ拡張

## 実行データ

【準備中】[Releases](https://github.com/shoma-ohkawa/AimRacing2026_Portfolio/releases) から `AimRacing2026_Build.zip` をダウンロードし、解凍して `AimRacing2026.exe` を起動します。

## 実行環境

- 通常プレイ: Windows PC で、キーボードまたはゲームパッドでプレイできます。
- 展示用の追加機材: Logitech G923(Logitech G HUB を使用)、外付けシフトレバー、WIZMO モーションチェア。接続すると、FFB とモーションチェアの連動を確認できます。
- 追加機材がない環境では、FFB の反力とモーションチェアの動きは体験できません。

## 操作方法

| 操作 | キーボード | ゲームパッド | 展示用 |
|---|---|---|---|
| ステアリング | ← → | 左スティック | G923 ハンドル |
| アクセル / 決定 | ↑ | RT | G923 のペダル |
| ブレーキ / キャンセル | ↓ | LT | G923 のペダル |
| シフトアップ | W | RB | 外付けシフトレバーの UP |
| シフトダウン | S | LB | 外付けシフトレバーの DOWN |

クラッチは使いません。展示では、外付けシフトレバーだけで変速します。

**AT / MT**: 開始メニューで選びます。AT は自動変速、MT は手動変速で、キーボード・ゲームパッド・外付けシフトレバーのいずれでも変速できます。

**FFB のモード切り替え**(G923 を使うとき)

| キー | モード |
|---|---|
| F6 | Child(小柄な体験者向け) |
| F7 | Standard(通常の展示用) |
| F8 | StrongShake(強めの演出用) |

**WIZMO の安全操作**(WIZMO を使うとき): F12 で安全停止、Shift + F12 で復帰します。WIZMO を使わないときは不要です。

進行の途中で使うキーは次のとおりです。

| 場面 | 操作 |
|---|---|
| Opening | ペダルを一度離してから踏む、または ↑キー で Menu へ |
| Menu | AT / MT を選び、アクセル(↑キー)を 2 回押して確定 |
| Intro | PageDown でイントロ映像をスキップ |

## Source について

自分が書いたスクリプトだけを入れています。Unity のプロジェクト全体(シーン、アセット、プレハブ)は入っていないため、このリポジトリだけではビルドできません。

| フォルダ | 内容 |
|---|---|
| `Source/GameManager/Flow` | State 遷移エンジン(遷移グラフ、進行、フェード、セッションのリフレッシュ) |
| `Source/GameManager/GameStates` | 各 State の実装 |
| `Source/Camera` | 3 画面出力(複数モニターへの分割表示) |
| `Source/Effect/RacingEnter` | レース突入演出 |
| `Source/UI` | Loading 画面、タイトルロゴ、残り時間 |
| `Source/Perf` | 計測の記録(性能・遷移時間)と自動周回 |
| `Source/Utility` | `SingletonMonoBehaviour`、`AppLog` |
| `Source/Editor` | エディタ拡張 |
| `Tools/PerfViewer` | 計測結果の集計とグラフ表示(Python・HTML) |

## 実装上の工夫

### State 遷移エンジン

- 「どの State でどのシーンを読むか」「次の State は何か」を、`GameFlowGraph` の 1 か所に書きます。
- 各 State は次の State を知らず、終わったら `AdvanceToNext()` を呼ぶだけです。State はシーン内の MonoBehaviour で、起動時に自分から `GameFlowRunner` へ登録します。
- 常駐シーン `Manager` を残し、State ごとのシーンを Additive でロード・アンロードします。
- フェードの秒数・色や Loading 画面の待ち時間は、すべてシーンの Inspector で設定できます。
- 画面が見える前に入力を受け付けないよう、準備完了のフラグが立つまで入力を無視します。

### 3 画面出力

- 映像は 1 回だけ描き、接続されているモニターの数だけ横に並べた RenderTexture から、モニターごとに該当部分を切り出して表示します。モニターごとにカメラを置く方式ではありません。
- 枚数・解像度・左右の並びは、起動時に自動で検出します(Inspector の手動設定はありません)。モニターが 1 枚でも起動します。縦画面のモニターには映像を割り当てません。

### 遷移の最中の演出

- 遷移フェード、Loading 画面、タイトルロゴの 3 つの層を、描画順を分けて重ねます。全モニター用の層は、モニターの数だけ Canvas を作ります。
- Load State は、自身の FadeIn が終わって画面が見えてから GC などのリフレッシュを実行します。重い処理が画面の表示前に出ません。

### 計測と性能改善

- 展示で連続稼働するため、リリースビルドを起動引数(`-perf`)で動かして記録します。引数がなければ何もしないので、本番の動作を変えません。
- 10 周の自動周回と放置監視を、起動引数だけで始められます。DLSS や映像を止めた条件と比べて、原因を切り分けます。
- 3 台の PC の実測(2026/10/19〜20)で、周回でメモリと VRAM が増える主因が DLSS だと分かりました。DLSS を止めると、`private_mb` の増加が約 98〜99% 減りました。ただし全部止めると走行中の FPS が約 3 割下がるため、Map のカメラだけ DLSS を残す条件なども比べました。
- 破棄する前に DLSS を止める対策は、展示用 PC の 10 周の実測(2026/10/22、1 回)では効きませんでした(増加量は基準と同じ範囲)。残る案は、Map のカメラを使い回すことと、暫定の「Map のカメラだけ DLSS を残す」条件です。

### ログ出力

- `AppLog` は `Debug.Log` のラッパーで、`Log` はリリースビルドで呼び出しごと除去します。`LogWarning` と `LogError` はリリースでも出力します。

## 注意事項

- WIZMO を使う場合は、起動前に安全確認を行ってください。F12 で出力を止められます。
- G923 が認識されないときは、G HUB と Windows の認識状態を確認してください。USB ポートを変えると、入力や FFB の認識状態が変わることがあります。
- `Source/` には、SDK 本体や認証情報、他のメンバーが担当したコードは入れていません。

**特殊機材がない環境での確認**: 主要なゲームプレイは、キーボードまたはゲームパッドで確認できます。FFB の反力とモーションチェアの動作は体験できません。実装は `Source/` とプレイ動画で確認できます。
